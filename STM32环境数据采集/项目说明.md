## 1. 这个项目做了什么

板载光敏电阻 **LS1** 接在 **PF8 = ADC3_IN6** 上。程序以 100ms 周期采样一次（单次转换仅 21µs，**不阻塞**），
经过「8 点滑动平均 + 一阶 IIR 低通」两级滤波后，换算成 0~100 的相对光强，
实时刷新到 3.5 寸彩屏上，同时通过串口输出 CSV 数据流。

主循环只有一句：

```c
while (1) { app_sched_run(); }
```

所有功能都是**任务表**里的一个任务，到点自动执行。加功能不用改 `main.c`。

## 2. 引脚占用（已逐脚核对官方 IO 分配表与原理图）

| 功能 | 引脚 | 说明 |
|---|---|---|
| **光照采集** | **PF8** (ADC3_IN6) | 板载 LS1 硬占用（IO 分配表标注 `N`），**插着 3.5 寸屏时依然干净** |
| LCD 背光 | PB0 | 经 S8050 驱动，**吃 3.3V 轨约 120mA** |
| LCD 触摸 | PB1 / PB2 / PF9 / PF10 / PF11 | 只做 IO 配置，本工程不做触摸交互 |
| LCD 数据/控制 | PD0/1/4/5/8/9/10/14/15、PE7~PE15、PG0、PG12 | FSMC 并口 |
| 心跳灯 | PB5 (LED0) | 低电平点亮，约 2.5Hz 翻转 |
| 报警灯 | PE5 (LED1) | 低电平点亮 |
| 蜂鸣器 | PB8 | **高电平鸣叫**（注意与 LED 相反） |
| 按键 | PE4 (KEY0) / PE3 (KEY1) / PA0 (WK_UP) | KEY0/1 低电平有效，WK_UP 高电平有效 |
| 24C02 | PB6 (SCL) / PB7 (SDA) | 软件 IIC，板载已有 4.7K 上拉，**不要再加上拉** |
| 调试串口 | PA9 / PA10 (USART1→CH340C) | 115200-8-N-1，**必须插上 P3 跳线帽** |
| SWD 下载 | PA13 / PA14 | **本工程绝不占用** |

### 跳线帽

| 标号 | 本工程要求 | 原因 |
|---|---|---|
| **P3** | **必须插上** | 否则板载 CH340 收不到串口输出 |
| **P7** | **建议拔掉** | `adc3_init()` 内部会顺手把 **PA1** 也配成模拟输入，拔掉 P7 可避免 TPAD/DAC 往 PA1 灌电流 |
| P5 / P6 | 无所谓 | 本项目用 F 口的 PF8，与 RS485(PA2/PA3)、CAN(PA11/PA12) 无关 |
| B0 / B1 | 都接 0 | 正常运行模式 |

### 三个"可扩展"机制

#### ① 时间片任务调度器 `App/app_sched.c`

所有功能都写成「进来干一点活立刻返回」的任务函数，由 **TIM7 提供的 1ms 硬件心跳**统一驱动。
主循环因此永不阻塞。

```c
static app_task_t g_tasks[] =
{
    { "sensor",  APP_SENSOR_PERIOD_MS,  0, app_sensor_task,  1, 0 },
    { "display", APP_DISPLAY_PERIOD_MS, 0, app_display_task, 1, 0 },
#if APP_USE_ALARM
    { "alarm",   APP_ALARM_PERIOD_MS,   0, app_alarm_task,   1, 0 },
#endif
#if APP_USE_KEY
    { "key",     APP_KEY_PERIOD_MS,     0, app_key_task,     1, 0 },
#endif
#if APP_USE_CONSOLE
    { "console", APP_CONSOLE_PERIOD_MS, 0, app_console_task, 1, 0 },
#endif
    { "io",      APP_IO_PERIOD_MS,      0, app_io_task,      0, 0 },  /* ★ 扩展槽 */
    /* ★★★ 新任务加在这里 ★★★ */
};
```

> **为什么不用 SysTick 做心跳**：官方 `delay.c` 的 `delay_us()` 把 SysTick 当成一个被反复重装的
> 普通递减计数器用，没有留下自由运行的节拍。所以另开 **TIM7**（基本定时器，无外部引脚、无引脚冲突），
> 两边互不干扰。

#### ② 通用传感器注册表 `App/app_sensor.c`

所有传感器实现同一组接口并登记到一张表里，**显示层和串口层只遍历这张表**。

```c
typedef struct {
    const char *name;          /* CSV 列名, 如 "LIGHT" */
    const char *label;         /* 界面标签, 如 "LIGHT INTENSITY" */
    const char *unit;
    uint8_t   (*init)(void);
    uint8_t   (*poll)(int32_t *out);
    int32_t     vmin, vmax;    /* 量程, 用来画条形图 */
    int32_t     value;         /* 运行时填写 */
    uint32_t    poll_cnt;
    uint8_t     online, enable;
    const char *(*level_text)(int32_t);   /* 可选钩子 */
    uint16_t    (*color_of)(int32_t);     /* 可选钩子 */
} app_sensor_t;
```

**往表里加一行 → 屏幕上自动多出一张卡片，串口 CSV 自动多出一列，显示模块一个字都不用改。**
卡片高度还会自动在大/中/小三种排版之间切换。

#### ③ 集中式配置 `App/app_config.h`

功能开关、周期、阈值、预留引脚宏全部集中一处，改功能不用翻代码。举几个：

```c
#define APP_USE_LIGHT     1     /* 光照采集（核心） */
#define APP_USE_ALARM     1     /* 阈值报警 */
#define APP_USE_EEPROM    1     /* 阈值掉电保存 */
#define APP_USE_DHT11     0     /* 预留: 温湿度 */
#define APP_USE_MQ2       0     /* 预留: 燃气 */
#define APP_USE_WIFI      0     /* 预留: 4G/WiFi 上传 */
```

## 4. 关键实现说明

### 4.1 光照采集：为什么没用官方的 `lsens_get_val()`

官方 `lsens.c` 的 `lsens_get_val()` 内部调用 `adc3_get_result_average(ch, 10)`，
而该函数**每采一次就 `delay_ms(5)`，取 10 次 = 50ms 纯阻塞**。
在一个以 100ms 为周期的任务里，这会吃掉一半 CPU 时间，与"实时显示"的目标相悖。

本工程的做法（`App/app_light.c`）：

```
每个 100ms 时间片:
  ① adc3_get_result(6)              单次转换, 约 21us, 不阻塞
  ② 写入 8 点环形缓冲, 求平均        去掉脉冲干扰
  ③ filt += (avg - filt) >> 2       一阶 IIR, 时间常数约 0.4s
  ④ percent = 100 - clamp(filt/40)  官方换算公式(实验20), 光越亮值越大
  ⑤ 分 5 级: V.DARK / DARK / NORMAL / BRIGHT / V.BRIGHT
```

开机**第一帧就是正确的**（滑动平均只除以已填充的点数，不用等缓冲填满）。

### 4.2 ⚠ 光敏相关的两个官方实现陷阱（已核实）

1. **`adc3.h` 里的 `ADC3_CHY = 1`、`ADC3_CHY_GPIO_PORT = GPIOA`、`ADC3_CHY_GPIO_PIN = PIN1`
   是残留默认值，和光敏无关。** 光敏真正的通道号在 `lsens.h` 的 `LSENS_ADC3_CHX = 6`，
   而 PF8 的"模拟输入"模式是 `lsens_init()` **自己**调 `sys_gpio_set(GPIOF, PIN8, ...)` 配好的。
   **切不可为了"改通道"去改 `adc.h`——那是 ADC1/2 的定义，改了没用还容易搞乱。**
2. **`adc3_init()` 会顺手把 PA1 也配成模拟输入**（无害的副作用）。这就是建议拔掉 P7 跳线帽的原因。

### 4.3 显示：局部刷新

绝不使用 `lcd_clear()` 整屏重画（那样每帧都会闪）。做法：

- 每个传感器有一份缓存（上一次的值 / 颜色 / 条形像素宽度 / 在线状态）；
- **只有变化时才重画对应的小矩形**；
- `lcd_show_xnum(x, y, val, 3, size, 0, color)` 的 `mode=0` 会用 `g_back_color`
  把高位补成空格，所以数字区域是**定宽自清除**的，不需要额外擦除；
- 状态栏降到 **1Hz** 刷新（运行时间每秒才变一次），省下大量无谓开销。

### 4.4 ⚠ 界面为什么只能显示英文

官方 `lcd.c` 的字库 `lcdfont.h` 只有 12/16/24/32 号 **ASCII** 点阵，
而 `lcd_show_string()` 的循环条件是：

```c
while ((*p <= '~') && (*p >= ' ')) { ... }
```

中文字节（> 0x7E）会让循环**立刻退出**，一个都画不出来。
要显示中文需要移植官方 **实验36 汉字显示实验** 的字库方案（需要字库文件）。

所以：**界面全英文，中文只出现在代码注释、串口输出和本文档里。**
串口输出之所以也是英文，是因为 GBK 编码的字符串字面量里可能出现 `0x5C`（反斜杠），
会被编译器当成转义或续行符——注释里写中文没这个问题，字符串里一律用 ASCII 最稳。

### 4.5 报警的滞回

如果光强正好卡在阈值上，不做滞回的话报警会以毫秒级频率反复通断，
蜂鸣器会发出刺耳的"塔塔"声。所以在阈值上下各留 `LIGHT_ALARM_HYST = 3` 的缓冲：
高于 `阈值+3` 才报警，低于 `阈值-3` 才解除。

### 4.6 报警电平极性（已从官方综合例程核实）

| 器件 | 极性 | 写法 |
|---|---|---|
| LED0 (PB5) / LED1 (PE5) | **低电平点亮** | `LED1(0)` = 亮 |
| BEEP (PB8) | **高电平鸣叫** | `BEEP(1)` = 响 |

（依据：实验48 综合测试 `beepplay.c:207  BEEP(1); /* 打开蜂鸣器 */`、实验38 `BEEP(1); /* 蜂鸣器短叫 */`）

### 4.7 运行开销

| 任务 | 周期 | 单次耗时 | CPU 占用 |
|---|---|---|---|
| sensor | 100 ms | ≈ 30 µs | < 0.1% |
| key | 20 ms | ≈ 10 µs | < 0.1% |
| alarm | 100 ms | ≈ 5 µs | ≈ 0 |
| display | 200 ms | 1 ~ 4 ms（仅变化区域） | 1 ~ 2% |
| console | 500 ms | ≈ 5 ms（printf 阻塞发送） | ≈ 1% |
| **合计** | | | **< 4%** |

余量极大，后面加 DHT11（一次约 5ms）、MQ-2、SD 卡写入都绰绰有余。

## 5. 编译与下载

### 5.1 编译（Keil MDK）

1. 双击 `Projects\MDK-ARM\STM32环境数据采集.uvprojx`；
2. 按 **F7** 或点 **Build**。应当得到 `0 Error(s), 0 Warning(s)`；
3. 产物在 `..\..\Output\EnvCollect.hex`（工程已配好 `Create HEX File`）。

> **不要切到 Arm Compiler 5。** 你的 MDK 是 **5.43a**，只装了 **AC6 (Arm Compiler 6.24)**，
> 没有 AC5。本工程已设为 `<uAC6>1</uAC6>`，直接用默认的 AC6 编译即可。
>
> 编译期加了几条告警抑制（`Options for Target → C/C++ → Misc Controls`）：
> `-Wno-unused-function -Wno-char-subscripts -Wno-self-assign -Wno-unused-parameter`。
> 这些告警全部来自**官方驱动代码**（`sys.h` 的 static 函数、`lcd.c` 用 char 下标访字库、
> `usart.c` 里 `x = x;` 防未用参数的写法），不是本项目的代码问题；抑制掉是为了让真正的告警浮出来。

### 5.2 下载（两条路，你手上都有）

| 方式 | 连接 | 说明 |
|---|---|---|
| **① SWD + ST-Link**（推荐） | ST-Link 的 SWDIO→PA13、SWCLK→PA14、GND、3.3V | 首次打开工程后需要设一次：<br>`Options for Target → Debug → 选 "ST-Link Debugger" → Settings → 确认端口是 SW` |
| **② ISP + CH340C**（备用） | USB Type-C 插 `USB_UART` 口 | 板载 CH340C 带 DTR/RTS 一键下载电路。用 **flymcu**（DTR 低电平复位 / RTS 高电平进 BootLoader），或把 **B0 跳到 1** 后手动复位 |

> 关于 ST-Link：如果你用的是**非 ST 原厂芯片**（比如 N32），
> ST 官方的 STM32CubeProgrammer / ST-Link Utility 会因 DEV_ID 不匹配而拒绝；
> 但 **Keil MDK 里的 ST-Link 驱动工作在 SWD 层、与芯片厂商无关，可以正常下载**。

### 5.3 上电现象

1. LCD 背光亮，标题栏出现；
2. 约 0.2 秒内首帧数据刷新；
3. 数值随遮光/照光实时变化，条形图跟着变长变短，颜色随等级变化（灰/蓝/绿/黄/红）；
4. LED0 (PB5) 以约 2.5Hz 闪烁（心跳）；
5. 串口（115200，XCOM/SSCOM）每 500ms 一行 CSV，开机时打印配置信息和任务表；
6. 遮光到超过阈值（默认 70%）时 LED1 常亮 + 蜂鸣器断续响。

## 7. 故障速查

| 现象 | 十有八九是 | 怎么办 |
|---|---|---|
| 屏白屏 / 花屏 | LCD 排座没插到底 | 断电重插排座，确认 2×17 针都到位 |
| 屏全黑，背光不亮 | PB0 没驱动 / 屏没供电 | 检查排座；`lcd_init()` 末尾有 `LCD_BL(1)` |
| 数值一直是 0 或 100 不动 | PF8 没被正确初始化 / 屏排座压到了 F 口 | 确认 `lsens_init()` 被调用（在 `app_light_sensor_init()` 里） |
| 数值乱跳 | 采样时间太短 / 没滤波 | 本工程已用 239.5 周期 + 双重滤波；若仍跳，检查 3.3V 是否干净 |
| 串口助手认不到端口 | Type-C 线"只充电不传数据" | 换线；正确应出现 **CH340** 串口 |
| 串口能开但收不到打印 | **P3 跳线帽没插** / 波特率不对 | 插上 P3；波特率必须 **115200** |
| 下载失败 / 找不到芯片 | PA13/PA14 被配成了普通 IO | BOOT0 拉高走 ISP 救；或用 ST-Link 的 "connect under reset" |
| 报警不响 | 阈值比当前光强高 | 按 KEY0 把阈值降下来，或用灯照 LS1 |
| 阈值改了但重启就还原 | 没按 WK_UP 保存 | 按一下 WK_UP；串口会打印 `threshold 70% saved to 24C02` |
| 打开工程提示找不到器件 | 没装器件包 | 装 `Keil.STM32F1xx_DFP`（本机已装 2.3.0） |
| 提示 `Arm Compiler 5 not found` | 被切成了 AC5 | `Options for Target → Target → ARM Compiler` 选 **V6** |
| 屏幕上有中文变成方块/乱码 | 官方字库只有 ASCII | 见 §4.4，中文需移植实验36 的字库方案 |
